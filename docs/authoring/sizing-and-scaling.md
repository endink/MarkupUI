# DPI 与缩放

Markup UI 按逻辑尺寸进行页面布局，由平台宿主根据实际尺寸与有效缩放确定物理绘制分辨率。

!!! note "宿主控件"
    宿主控件在引擎界面中承载 HTML 页面，其布局空间决定页面的可用显示区域。

    - **Unreal Engine**：UMG 中的 `MarkupUIWidget`。
    - **Unity**：UI Toolkit 中的 `MarkupHtmlElement`。

## 逻辑尺寸与物理分辨率

CSS 中的 `px` 是逻辑单位，不直接等同于屏幕上的物理像素。普通均匀缩放下，物理尺寸约为逻辑尺寸乘以有效缩放，并取整为像素尺寸。

例如，`800 × 600` 的逻辑显示区域在有效缩放为 `2` 时，对应 `1600 × 1200` 的物理分辨率。页面中的 `16px` 字号无需为了适配这一比例再手动改为 `32px`。

## 平台说明

各平台的 DPI 来源、缩放计算及呈现行为由其宿主处理，详细说明见：

- [Unreal Engine：DPI 与缩放](../ue/usage/dpi-and-scaling.md)：累计布局缩放、项目 DPI 曲线及 Render Transform。
- [Unity：DPI 与缩放](../unity/usage/dpi-and-scaling.md)：面板像素密度、元素缩放及离屏视口。

## 布局与显示质量

改变逻辑显示区域可能触发换行和重新布局；提高像素密度则改变绘制分辨率。额外放大最终画面可能引入重采样，低分辨率图片也不会因 DPI 提高而增加细节。

字号表示文字排版尺度，不等于可见字形的包围盒高度。图片资源应满足目标显示密度；抗锯齿不能替代正确的视口分辨率或图片源分辨率。

页面尺寸、百分比与布局约束见[布局与尺寸](layout-and-styles.md)。
